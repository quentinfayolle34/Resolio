# Resolio — notes pour Claude

Application mobile de résolutions par jour / semaine, en **français**. Projet **Capacitor 8** : Android (`android/`) et iPhone (`ios/`), pas de version web publiée.

## Architecture
- Toute l'app est dans `www/index.html` : HTML + CSS + JavaScript vanilla, **sans bundler ni framework**. Garder ce choix sauf demande explicite.
- Les plugins Capacitor sont appelés sans import : `plugin('Preferences')`, `plugin('App')`, `plugin('Browser')`, `plugin('Share')`, `plugin('Filesystem')` (helper basé sur `window.Capacitor`). Un plugin ajouté doit aussi être installé avec npm puis `npx cap sync`.
- `IS_APP` est vrai dans l'app native ; dans le navigateur (`npm run dev`) tout doit aussi fonctionner.
- **iOS** : projet `ios/` (Swift Package Manager, iPhone seulement, portrait, français). `Info.plist` : schéma `com.quentinfayolle.resolio` (retour de connexion), textes d'autorisation appareil photo / photos. Construit par `.github/workflows/ios.yml` sur macOS (compilation à chaque push ; signature automatique + envoi TestFlight sur tag `v*` avec les secrets `APPLE_TEAM_ID`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8_BASE64`). `IS_ANDROID` / `IS_IOS_APP` : Temps d'écran seulement sur Android (`screenPlugin()` nul ailleurs) ; bouton « Continuer avec Apple » (`backend.signInApple`, OAuth Supabase `apple`) seulement sur iPhone (obligatoire pour l'App Store, règle 4.8). Icône iOS : 1024 px opaque générée par `scripts/generate-icons.py`.

## Données : Supabase uniquement (dossier `supabase/`)
- L'app est **100 % en ligne** : aucune donnée métier stockée sur le téléphone (seule la session Supabase, via Preferences). Ne pas réintroduire de stockage local des données.
- Config publique dans `www/config.js` (URL + clé publishable). Jamais de clé `service_role`/`secret` dans le dépôt.
- Bibliothèque : `www/vendor/supabase.js` (UMD, `window.supabase`), mise à jour par `npm run vendor`.
- Tout l'accès serveur passe par l'objet `backend` (`createSupabaseBackend()`), interface : auth (`signIn`, `signUp`, `signInGoogle`, `signInApple`, `handleDeepLink`, `resetPassword`, `updatePassword`, `signOut`, `deleteAccount`) + données (`loadAll`, `saveProfile`, `addUserSport`, `upsertScreenTime`, `upsertSteps`, `uploadAvatar`, `upsertGoals`, `upsertWeeks`, `insertEntries`, `deleteEntries`, `replaceAllData`) + amis (`loadSocial`, `loadPosts`, `findByCode`, `requestFriend`, `acceptFriend`, `removeFriendship`, `uploadPostPhoto`, `createPost`, `deletePost`, `setPostLike`, `publishResult`, `loadResults`, `setResultLike`, `savePublicStats`). Les tests remplacent cet objet par `window.__RESOLIO_TEST_BACKEND__`.
- État en mémoire (`state.profile`, `state.goals`, `state.weeks`) chargé par `loadData()`. Écritures : `saveGoals` / `saveWeek` / `saveProfile` mettent à jour l'écran puis envoient via `write()` (file d'attente ; en cas d'échec : message + rechargement depuis la base). `saveWeek` calcule les enregistrements ajoutés/supprimés.
- `state.phase` : `loading` | `config` | `auth` | `offline` | `setup` (configuration pas terminée : `profile.startWeek` vide) | `app`.
- Premier lancement (`viewSetup`) : prénom / nom puis l'utilisateur ajoute **lui-même** ses résolutions (aucune résolution par défaut) ; « C'est parti » exige au moins une résolution et enregistre `startWeek`.
- **Périodes** : `g.period` = `day` | `week` (défaut `week`), fixée à la création (`PERIODS`). Mois / année **retirés** (migration `20261126200000` : supprimés en base + contrainte ; `goalsList()` ignore ceux qui resteraient ; les helpers `periodStart` etc. gèrent encore month/year, sans usage). Une période = sa date de début (jour, lundi) : `periodStart` / `periodNext` / `periodPrev`. `createdWeek`, `archivedWeek`, `targetHistory[].from`, `injuries[]` contiennent des débuts de période de l'objectif (noms hérités).
- Les enregistrements restent rangés par semaine (`state.weeks[lundi].entries`, colonne `entries.week`) ; `entriesBetween(a, b)` les récupère pour n'importe quelle période ; `computePeriod(p, start, entries)` calcule le bilan.
- **Catégories** (`CATS`, dans l'ordre de l'assistant) : `muscu`, `cardio` (sports choisis dans `g.activities`), `reading`, `meditation`, `reduce` (unité libre dans `g.unit`, `isLimit`), `screen`, `steps`, `revision`, `other`. `sport` = ancienne catégorie (convertie par la migration `20261127200000` ; `goalFromRow` la convertit aussi), `SPORT_CATS` pour les badges.
- **Assistant de création** (`openWizard`, `wizSteps`, `renderWizard`) dans la page plein écran `#page` (`openPage` / `closePage`, z-index 30) : période → catégorie → nom + emoji → étapes selon la catégorie (`metrics`/`targets`, `sports` pour cardio, `reduce`, `scope`/`pick` pour l'écran, `targets`/`health` pour les pas, `type` pour Autres) → `share` (semaine, ou Réduire/Écran) → `summary` → `saveGoal`. Il réutilise `goalDraft` et les actions `ge-*`/`step`/`emoji` ; `goalDraft._wiz` = étape. La modification (`openGoalEditor(id)`) s'affiche dans la même page (formulaire complet). Premier lancement : prénom/nom → « Choisir ma première résolution » (`setup-next`) → assistant → liste + « C'est parti ».
- **Saisie** : les mesures de la catégorie non suivies restent proposées en facultatif (durée, distance, pages).
- **Réduire / Temps d'écran dépassés** → `publishLost` (publication « ❌ Perdu », seulement si `g.shared`), une fois par période grâce aux mémos `profile.goalMarks[goalId] = { done, lost }` (colonne `profiles.goal_marks`, `marked` / `setMarks`).
- **Nombre de pas** (`cat: 'steps'`, mesure `steps`) : plugin `@capgo/capacitor-health` (`plugin('Health')`, Health Connect / HealthKit), `syncSteps(ask)` au chargement et au retour (14 derniers jours) → `state.steps[date]` + table `daily_steps` ; `checkSyncedGoals()` met en file la popup « Résolution tenue » (`donePrompts`, `flushDonePrompts` après les bilans) et publie les « Perdu » du temps d'écran. Android : minSdk 26, seules la permission `READ_STEPS` est gardée (`tools:node="remove"` pour les autres) ; iOS : `App.entitlements` (HealthKit) + textes `NSHealth*`. Politique de confidentialité : `www/privacypolicy.html` (demandée par Health Connect). Tests : `window.__HEALTH_TEST__`.
- **Import Strava / Liftoff (à faire)** : `entries.source` (`manual`/`strava`/`liftoff`/`health`) + `entries.external_id` (index unique par utilisateur) sont prêts. Strava exige un secret côté serveur → Edge Function Supabase (OAuth + webhook) ; Liftoff n'a pas d'API publique connue → passer par Santé / Health Connect s'il y écrit ses séances.
- **Mesures** (`g.metrics`, voir `metricsOf`) : `count`, `time` (min), `distance` (km), `pages`, `quantity`, `days`, `once`, `limit`. Lecture et sport : plusieurs mesures possibles ; objectifs chiffrés par mesure dans `targetHistory[].targets` (`targetsFor`). Une résolution est tenue quand toutes ses mesures sont atteintes (`evalGoal`), ou pour `limit` non dépassées. Les anciennes résolutions sans `metrics` sont déduites de `type`.
- **Temps d'écran** (`cat: 'screen'`, Android uniquement — carte grisée dans l'assistant ailleurs ; mesure `limit` en minutes, sous-type `total`/`categories`/`apps`, sélection dans `g.activities`) : lu sur le téléphone par le module natif `android/.../ScreenTimePlugin.java` (`plugin('ScreenTime')` : `hasPermission`, `openSettings`, `getDailyUsage({ days })`, à partir de `UsageStatsManager.queryEvents`), enregistré par appli et par jour dans `public.screen_time`, chargé dans `state.screen[date]`. `syncScreenTime()` tourne au chargement (avant les bilans) et au retour dans l'app. iOS : pas d'équivalent (API Screen Time d'Apple fermée). Tests : `window.__SCREEN_TIME_TEST__` remplace le module.
- **Sports** : liste commune `public.sports` (lecture seule) + sports perso `public.user_sports` (privés), fusionnés dans `state.sports` (`mergeSports`), ajout via `backend.addUserSport`.
- **Badges** : 12 badges (`BADGES`), 5 niveaux chacun (`TIERS` : Bronze, Argent, Or, Platine, Diamant), seuils dans `steps`, valeur calculée par `computeStats()` ; `badgeLevel()` donne le niveau et la progression. « Livre terminé » = `entry.finished` (colonne `entries.book_finished`).
- Type `daily` (« chaque jour », catégorie Autre) : seulement pour la période semaine (max 7).
- `maintenance()` : clôture les semaines passées (`weeks.result` = résolutions hebdo seulement) puis affiche les **bilans de fin de période** (jour, semaine) non encore vus, mémorisés dans `profile.recaps[p]` (colonne `profiles.recaps`).
- Un changement d'objectif chiffré s'ajoute à `targetHistory` à partir de la période en cours ; les périodes passées gardent leur chiffre.
- Schéma : `supabase/migrations/*.sql` (tables `profiles`, `goals`, `weeks`, `entries`, `sports`, `user_sports`, `screen_time`, `friendships`, `posts`, `post_likes`, `period_results`, `result_likes`, `daily_steps`, buckets `avatars` et `posts`, RLS « chacun ses lignes » + lecture par les amis, fonction `delete_my_account`) ; `supabase/reset.sql` pour tout effacer. Nouveau champ = nouvelle migration + conversions `xxxToRow` / `xxxFromRow`.
- Connexion Google / liens email : PKCE, retour par le lien `com.quentinfayolle.resolio://auth-callback` (ou `://reset-password`) déclaré dans `AndroidManifest.xml`.
- **Amis** (onglet `amis`, ouvert par défaut) : module `social` (`loadSocial`, `viewFriends`, `openFriendsSheet`, `openFriendProfile`). Tables `friendships` (pending/accepted, `is_friend()`), `posts` + `post_likes`, `period_results` + `result_likes` ; RPC `find_user_by_code`, `my_social_profiles` (stats publiques seulement si amis). `profiles.friend_code` (ex. `QUEN-8D5F`, immuable), `public_stats` (série + niveaux de badges, `publishPublicStats`).
  - `g.shared` (éditeur de résolution, Public par défaut, Privé pour `reduce`/`screen`, pas pour `day`) = visible dans la rétrospective.
  - Fil : **une publication seulement quand une résolution passe de « pas tenue » à « tenue »** sur sa période (`goalDoneAt` avant/après la saisie dans `saveEntry` / `toggleDay` ; pour les pas, après la synchro) → popup `openDoneSheet` (photo `#done-photo`, texte `#done-note`, « Publier » = `publishDone`, ou « Ne pas publier »). Liée à la saisie qui a tenu l'objectif (`entry_id`, supprimée avec elle ; nul pour les pas et les « Perdu »). Les maximums (`reduce`, `screen`) ne publient que « Perdu ».
  - Rétrospective (semaine seulement, `RETRO_PERIODS`) : `publishResults()` envoie le bilan de la période terminée (résolutions partagées seulement, rien si aucune), mémorisé dans `profile.retroPublished`. `maybeAutoRetro()` l'ouvre en plein écran (`#retro`, `renderRetro`) après les bilans perso, si des amis ont publié, une seule fois (`profile.retroSeen`) et dans les 3 jours. Le sous-onglet Semaine (`openRetroFor`) montre toujours la dernière.
- **Popups du bas** (`openSheet` / `closeSheet`) : barre collante avec ✕ (`.sh-x`, `data-act=close-sheet`) sur toutes ; le fond est figé pendant l'ouverture (`lockScroll` / `unlockScroll` : body en `position:fixed`, position restaurée à la fermeture).
- **Historique** : calendrier du mois en haut (`viewCalendar`, `calMonth`, ✓ = au moins une saisie hors `reduce`, `isActivity`), appui sur un jour → `openDaySheet` (résolutions du jour + saisies), puis les bilans.
- Les données de l'ancienne version locale (clé Preferences `resolio-v1`) sont proposées à l'import au premier lancement d'un compte vide.

## Style
- Thème sombre, jaune `#f5c518` utilisé avec parcimonie (accent seulement). Polices Archivo (titres) + Inter (texte), embarquées dans `www/fonts`.
- Mobile d'abord (≈ 390 px de large), zones tactiles ≥ 44 px, safe areas via `--safe-area-inset-*` (injectées par Capacitor SystemBars) avec repli `env()`.
- Textes d'interface en français, ton direct et motivant, tutoiement.

## Commandes
- `npm run dev` : tester dans le navigateur (http://localhost:5173) — URL à autoriser dans Supabase
- `npx cap sync android` : copier `www/` dans le projet Android après une modification
- `npm run android` : ouvrir dans Android Studio
- `npx cap sync ios` : copier `www/` dans le projet iOS (Xcode seulement sur Mac ; sinon la CI construit l'app)
- Icônes : `python3 scripts/generate-icons.py`

## Publication
- Version dans `package.json`, puis tag `vX.Y.Z` → GitHub Actions publie l'APK signé dans Releases et envoie l'app iPhone sur TestFlight.
- Ne jamais committer de keystore (`*.keystore`, `*.jks`), de clé Apple (`*.p8`, `*.p12`, `*.mobileprovision`) ni de mot de passe.
